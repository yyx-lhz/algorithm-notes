# LeetCode 153 — 寻找旋转排序数组中的最小值

## 题目

假设一个按升序排列的数组在某个未知点进行了旋转（例如 `[0,1,2,4,5,6,7]` 旋转后变成 `[4,5,6,7,0,1,2]`）。请找出数组中的最小元素。数组中不含重复元素。

## 核心思路

每次取中间点 `mid`，跟**最右边的值** `nums[right]` 比较。分两种情况：

### 情况一：`nums[mid] < nums[right]`

```
        mid          right
         │             │
   [4, 5, 0, 1, 2, 3]
         └─────┘
         这一段递增
```

`mid` 到 `right` 是递增的 → 这一段没有"断崖" → 最小值一定在 `mid` **左边（包括 mid）**。

→ `right = mid`（mid 自己可能就是最小值，不能跳过）

### 情况二：`nums[mid] > nums[right]`

```
   left       mid          right
    │          │             │
   [4, 5, 6, 7, 0, 1, 2]
             └──────────┘
              这里有断崖
```

`mid` 比 `right` 大 → 旋转的"断崖"一定在 `mid` 到 `right` 之间 → 最小值一定在 `mid` **右边**。

→ `left = mid + 1`（mid 自己肯定不是最小值，可以跳过）

### 为什么只和最右边比？

- 跟 `left` 比无法判断"断崖"在哪一侧
- `nums[mid] < nums[right]` → 右侧有序 → 最小值在左侧
- `nums[mid] > nums[right]` → 断崖在右侧 → 最小值在右侧

---

## 代码实现

```python
class Solution:
    def findMin(self, nums: list[int]) -> int:
        left, right = 0, len(nums) - 1

        while left < right:
            mid = (left + right) // 2

            if nums[mid] < nums[right]:
                # 右侧有序，最小值在左侧（含 mid）
                right = mid
            else:
                # nums[mid] > nums[right]，断崖在右侧，最小值在 mid 右边
                left = mid + 1

        # left == right 时即为最小值位置
        return nums[left]
```

## 图解

### 例 1：`[4, 5, 6, 7, 0, 1, 2]`

```
初始: left=0, right=6
  nums = [4, 5, 6, 7, 0, 1, 2]
                       ↑ mid=3 (值=7)

  nums[mid]=7 > nums[right]=2 → 断崖在右侧 → left = mid+1 = 4

第1步后: left=4, right=6
  nums = [4, 5, 6, 7, 0, 1, 2]
                    ↑ mid=5 (值=1)

  nums[mid]=1 < nums[right]=2 → 右侧有序 → right = mid = 5

第2步后: left=4, right=5
  nums = [4, 5, 6, 7, 0, 1, 2]
                    ↑ mid=4 (值=0)

  nums[mid]=0 < nums[right]=1 → 右侧有序 → right = mid = 4

第3步后: left=4, right=4 → 退出循环 → 返回 nums[4] = 0 ✅
```

### 例 2：`[1, 2, 3, 4, 5]`（未旋转）

```
初始: left=0, right=4
  nums[mid]=3 < nums[right]=5 → right = mid = 2
  nums[mid]=2 < nums[right]=3 → right = mid = 1
  nums[mid]=1 < nums[right]=2 → right = mid = 0
  退出 → 返回 nums[0] = 1 ✅
```

## 复杂度

- **时间复杂度**：O(log n)——每次砍掉一半
- **空间复杂度**：O(1)——只用了几个指针

---

## 核心技巧

> 二分查找的边界条件失误率很高。一个简单的验证方法：把 `[1, 3]` 和 `[3, 1]` 这两种最小情况代入代码，检查是否会死循环或跳错。
