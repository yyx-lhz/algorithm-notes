# Day 15 · LeetCode 146. LRU 缓存

## 思路

哈希表 `self.cache` 保存 key 到 Node 的映射，快速找到节点；双向链表维护使用顺序。头部是最近使用的节点，尾部是最久未使用的节点。LRU 按最近使用时间淘汰，不是按使用次数淘汰。

每个 Node 保存 key、value、prev、next。保留 key 是为了淘汰节点时，也能删除哈希表里的对应记录。

两个哨兵节点 head 和 tail 在初始化时相连，统一空链表和首尾节点的操作。

## 操作过程

- `remove_node`：把节点从当前位置摘下，让它的前后节点互相连接。
- `add_node`：把节点插入 head 后面，标记为最近使用。
- `get`：key 不存在时返回 -1；存在时摘下该节点、移到头部，再返回 value。读取不会淘汰其他节点。
- `put`：key 已存在时更新 value、移到头部并 return；不存在时创建 Node，加入哈希表并插到头部。超过容量时，删除 tail.prev，同时删除哈希表中的记录。

完整 Python 3 代码：[146-lru-cache.py](./146-lru-cache.py)。

## 本次踩坑

1. Python 统一使用 4 个空格缩进，各方法的 def 必须对齐；构造方法写作 `__init__`。
2. 更新已有 key 后必须 return，否则会继续创建重复节点，造成哈希表和链表不一致。
3. 新增节点后不能在容量检查前 return，否则淘汰逻辑永远无法执行。

## 复杂度

- get、put：平均时间 O(1)。
- 空间：O(capacity)。
